AWS Organizations

Gerencie e governe várias contas AWS de forma central: criar contas, agrupá-las em OUs, aplicar políticas e ter uma fatura única.Centrally manage and govern many AWS accounts: create accounts, group them into OUs, apply policies and get a single bill.

Management account

Conta que administra a organização. SCPs não afetam usuários e roles dela, só as contas-membro.The account that administers the organization. SCPs do not affect its users and roles, only member accounts.

Member accounts

As demais contas. Cada conta AWS é um limite natural de permissão, segurança, custo e carga de trabalho.All other accounts. Each AWS account is a natural boundary for permissions, security, cost and workloads.

OU

Organizational Unit: grupo de contas (por exemplo, as que atendem a uma aplicação ou a um ambiente). Políticas anexadas a uma OU valem para as contas dentro dela.Organizational Unit: a group of accounts (for example those serving one application or environment). Policies attached to an OU apply to the accounts inside it.

SCP

Service Control Policy: define o máximo de permissões disponível para IAM users e roles das contas. Não concede nada.Service Control Policy: defines the maximum permissions available to IAM users and roles in the accounts. It grants nothing.

Como fica o resto da AWSWhat the rest of AWS looks like

Cada conta é um ambiente completo e isolado: a conta dev tem sua própria VPC, seu RDS e seus serviços; a prod tem os dela. Nada é compartilhado, a não ser que você libere (por exemplo, a imagem Docker no ECR de uma conta de tooling). O mesmo código sobe nas duas contas; só muda para onde a pipeline aponta, via OIDC, com uma role por conta.Each account is a full, isolated environment: the dev account has its own VPC, RDS and services; prod has its own. Nothing is shared unless you allow it (for example, the Docker image in the ECR of a tooling account). The same code ships to both accounts; only where the pipeline points changes, through OIDC, with one role per account.

Por que separar contas por ambienteWhy separate accounts by environment

A AWS recomenda usar várias contas para separar cargas de trabalho, em vez de uma só. Por padrão não existe acesso entre contas: se produção e não-produção ficam em contas distintas, elas permanecem isoladas até você liberar explicitamente. O número de contas não altera a cobrança, que é baseada no uso dos recursos.AWS recommends using several accounts to separate workloads rather than a single one. By default there is no access between accounts: if production and non-production live in different accounts, they stay isolated until you explicitly allow access. The number of accounts does not change billing, which is based on resource usage.

Como funcionaHow it works

  • Só existem regras de permissão (allow), não de bloqueio. Um SG novo não tem regra inbound, então nenhum tráfego de entrada é permitido até você adicionar.Rules are allow only, no deny. A new SG has no inbound rules, so no inbound traffic is allowed until you add some.

  • Stateful: a resposta a um tráfego permitido é liberada independentemente das regras do outro sentido. Por isso o outbound de um banco pode ficar vazio e ele ainda responde ao que o inbound autorizou.the response to allowed traffic is permitted regardless of the other direction's rules. NS & SOA

Ao criar uma zona pública, o Route 53 cria os registros NS (quatro name servers) e SOA. Para que a internet use essa zona, vá ao registrador do domínio (onde ele foi registrado) e configure os quatro name servers do NS padrão da zona. Para delegar um subdomínio a outra zona, crie um NS na zona do domínio raiz.When you create a public zone, Route 53 creates the NS records (four name servers) and SOA. For the internet to use that zone, go to the domain's registrar (where it was registered) and set the four name servers from the zone's default NS record. To delegate a subdomain to another zone, create an NS record in the root domain's zone.

Apontar o domínio para o ALBPointing the domain at the ALB

Crie um registro Alias do tipo A (e AAAA, se o ALB tiver IPv6) para o ALB. Quando o IP do load balancer muda, o Route 53 passa a responder com o novo sem você fazer nada. Para um alias a um recurso AWS você não define o TTL (vale o padrão do recurso) e não paga a consulta. O Alias funciona também no apex (exemplo.com.br), onde o CNAME não é permitido.Create an Alias record of type A (and AAAA, if the ALB has IPv6) for the ALB. When the load balancer's IP changes, Route 53 starts answering with the new one without you doing anything. For an alias to an AWS resource you do not set the TTL (the resource's default applies) and queries are not charged. Alias also works at the apex (example.com), where CNAME is not allowed.
