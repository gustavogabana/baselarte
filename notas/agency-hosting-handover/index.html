Uma stack padrão por tipo de projetoOne default stack per project type

Uma agência pequena ganha dinheiro repetindo o que já sabe fazer bem. Escolher a hospedagem do zero a cada cliente custa horas e gera um parque de projetos diferentes entre si, cada um com o seu jeito de publicar, de quebrar e de ser consertado. O melhor é ter um padrão por tipo de projeto e só sair dele com motivo.A small agency makes money by repeating what it already does well. Picking hosting from scratch for every client costs hours and leaves a fleet of projects that are all different: each one deploys, breaks and gets fixed its own way. Better to have one default per project type and only leave it for a reason.

Para landing pages e sites institucionais, um site estático é quase sempre a resposta certa: não tem servidor para atualizar, não tem banco para invadir, custa perto de zero e aguenta pico de tráfego de campanha sem ninguém acordar de madrugada.For landing pages and company websites, a static site is almost always the right answer: no server to patch, no database to breach, close to zero cost, and it survives a campaign traffic spike without anyone waking up at night.

O fluxo de trabalhoThe workflow

O mesmo fluxo para todos os clientes: código no Git, cada mudança vira um preview com URL própria para o cliente aprovar, e o merge na branch principal publica em produção.The same workflow for every client: code in Git, every change becomes a preview with its own URL for the client to approve, and the merge into the main branch publishes to production.

  • Um repositório por cliente, numa organização do GitHub da agência enquanto o projeto está em desenvolvimento (ou já na do cliente, se ele tiver uma).One repository per client, in the agency's GitHub organization while the project is in development (or already in the client's, if they have one).
  • Variáveis de ambiente na plataforma, nunca no código. Liste todas no README (nome e para que serve, sem o valor).Environment variables on the platform, never in the code. List them all in the README (name and purpose, never the value).
  • Domínio de teste (o *.pages.dev, *.netlify.app ou *.vercel.app) até a aprovação; o domínio do cliente só entra no go-live.Test domain (the *.pages.dev, *.netlify.app or *.vercel.app) until approval; the client's domain only comes in at go-live.
  • Rollback é um clique: as três plataformas guardam os deploys anteriores e permitem voltar para qualquer um.Rollback is one click: all three platforms keep previous deploys and let you go back to any of them.

De quem são as contasWho owns the accounts

Há dois modelos honestos. O que não é honesto é deixar o cliente sem saber qual dos dois ele contratou.There are two honest models. What is not honest is leaving the client unaware of which one they signed up for.

No modelo gerenciado pela agência, lembre que planos gratuitos com restrição de uso comercial (como o Hobby da Vercel) não servem para site de cliente. Use o plano pago do time da agência e repasse o custo.In the agency-managed model, remember that free plans with commercial-use restrictions (like Vercel's Hobby) do not cover client sites. Use the agency team's paid plan and pass the cost on.

O que entregar ao clienteWhat to hand over to the client

O site no ar não é a entrega inteira. A entrega é o cliente conseguir continuar sem você, mesmo que ele prefira não fazer isso. Monte um pacote de entrega igual para todo projeto:The live site is not the whole delivery. The delivery is the client being able to carry on without you, even if they would rather not. Build the same handover package for every project:

Checklist de go-liveGo-live checklist

  1. Domínio do cliente apontado, HTTPS ativo, www redirecionando para o principal (ou o contrário).Client domain pointed, HTTPS on, www redirecting to the main host (or the other way round).
  2. Formulários testados de ponta a ponta: a mensagem chega na caixa certa e não cai no spam.Forms tested end to end: the message reaches the right inbox and does not land in spam.
  3. Título, descrição e imagem de compartilhamento em cada página; sitemap.xml e robots.txt publicados; Search Console verificado.Title, description and share image on every page; sitemap.xml and robots.txt published; Search Console verified.
  4. Teste no celular de verdade, não só no modo responsivo do navegador.Test on a real phone, not just the browser's responsive mode.
  5. Página 404, favicon, redirecionamentos das URLs antigas (se o site substituiu outro).404 page, favicon, redirects from old URLs (if the site replaced another one).
  6. Monitor de disponibilidade simples (UptimeRobot, Better Stack) avisando a agência e o cliente.A simple uptime monitor (UptimeRobot, Better Stack) alerting the agency and the client.
  7. Pacote de entrega enviado e termo de entrega assinado.Handover package sent and delivery acceptance signed.
Depois do go-live, ofereça manutenção com escopo claro (atualizações, pequenas alterações por mês, monitoramento). Sites estáticos quase não quebram sozinhos; o que o cliente compra é ter alguém para chamar.After go-live, offer maintenance with a clear scope (updates, small changes per month, monitoring). Static sites almost never break on their own; what the client buys is someone to call.

Cola e revisãoCheat sheet and review

  • Landing page ou institucional: site estático no Cloudflare Pages ou Netlify.Landing page or company site: a static site on Cloudflare Pages or Netlify.
  • App com servidor: Vercel no plano pago ou Netlify, com Supabase.App with a server: Vercel on a paid plan or Netlify, with Supabase.
  • Preview por PR, aprovação por escrito, merge publica, rollback em um clique.Preview per PR, written approval, merge publishes, one-click rollback.
  • Domínio sempre do cliente; o resto depende do modelo combinado.The domain always belongs to the client; the rest depends on the agreed model.
  • Entrega = código, acessos, DNS, README, manual, analytics, privacidade e termo assinado.Handover = code, access, DNS, README, guide, analytics, privacy and a signed acceptance.
