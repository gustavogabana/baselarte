O que é o SMTPWhat SMTP is

SMTP (Simple Mail Transfer Protocol) é o protocolo que empurra uma mensagem de um servidor para outro até ela chegar ao servidor de quem recebe. Ele só entrega; quem lê a caixa de entrada depois usa outro protocolo (IMAP ou POP3). Pense no correio: o SMTP é o caminhão que leva a carta de agência em agência; o IMAP é você abrindo a caixa postal.SMTP (Simple Mail Transfer Protocol) is the protocol that pushes a message from one server to another until it reaches the recipient's server. It only delivers; reading the inbox later uses another protocol (IMAP or POP3). Think of the postal service: SMTP is the truck carrying the letter from office to office; IMAP is you opening your mailbox.

É um protocolo de texto, nascido em 1982 e hoje definido na RFC 5321. Foi desenhado quando todo mundo se conhecia, então não tinha autenticação nem criptografia. Quase tudo o que é "segurança de e-mail" é uma camada colocada por cima depois (seção 3).It is a text protocol, born in 1982 and now defined in RFC 5321. It was designed when everyone knew each other, so it had no authentication and no encryption. Almost everything called "email security" is a layer added on top later (section 3).

1. A conversa, comando a comando1. The conversation, command by command

Cliente e servidor trocam linhas de texto. O servidor responde com um código de três dígitos: 2xx deu certo, 3xx continue, 4xx erro temporário (tente de novo depois), 5xx erro permanente (desista). Esta é uma sessão real contra o Mailpit (seção 5); as linhas numeradas 2xx, 354 e 221 são do servidor, o resto eu digitei:Client and server exchange lines of text. The server answers with a three-digit code: 2xx worked, 3xx keep going, 4xx temporary error (try again later), 5xx permanent error (give up). Envelope não é cabeçalho. O MAIL FROM do envelope e o From: que o leitor vê são coisas separadas, e o servidor não exige que combinem. 2. Portas: 25, 587, 4652. Ports: 25, 587, 465

O SMTP usa portas diferentes para papéis diferentes. Separar os papéis é a primeira decisão de segurança: quem envia mensagem como usuário deve se autenticar; quem só recebe de outros servidores, não.SMTP uses different ports for different roles. Separating the roles is the first security decision: someone sending as a user must authenticate; a server only receiving from other servers does not.

Para a sua aplicação enviar e-mail: use a 465 (TLS implícito) ou a 587 (STARTTLS), sempre com usuário e senha, nunca a 25. That is why people hosting an app usually send through a relay service (SES, Postmark, Mailgun, Resend) on 587/465 instead of running their own MTA.

3.1 Transporte: STARTTLS ou TLS implícito3.1 Transport: STARTTLS or implicit TLS

Há dois jeitos de criptografar. No TLS implícito (porta 465) o TLS começa antes de qualquer palavra do SMTP. No STARTTLS (587, 25) a conexão começa em texto puro, o servidor anuncia 250-STARTTLS no EHLO, o cliente pede STARTTLS e só então a conexão é trocada por uma criptografada.There are two ways to encrypt. With implicit TLS (port 465) TLS starts before any SMTP word. With STARTTLS (587, 25) the connection starts in plain text, the server announces 250-STARTTLS in EHLO, the client sends STARTTLS and only then is the connection upgraded to an encrypted one.

O ataque de downgrade. Como o STARTTLS é negociado em texto puro, quem está no meio da rede pode apagar a linha 250-STARTTLS da resposta. Um cliente que trata o TLS como "se possível" segue em texto puro sem avisar. A defesa: o cliente exige TLS e aborta se ele faltar. É o que o Mailpit faz com MP_SMTP_REQUIRE_STARTTLS, e o que o laboratório mostra com o erro 530 Must issue a STARTTLS command first.The downgrade attack. Because STARTTLS is negotiated in plain text, someone in the middle of the network can strip the 250-STARTTLS line from the reply. A client that treats TLS as "if possible" carries on in plain text without warning. The defence: the client requires TLS and aborts if it is missing. That is what Mailpit does with MP_SMTP_REQUIRE_STARTTLS, and what the lab shows with the 530 Must issue a STARTTLS command first error.

Entre servidores (porta 25) o problema é maior: não há como exigir TLS de qualquer destino, porque muitos servidores antigos ainda não o oferecem. Por isso o TLS ali é oportunista (criptografa se der, e aceita qualquer certificado). Duas tecnologias fecham essa brecha para o seu domínio:Between servers (port 25) the problem is bigger: you cannot require TLS from every destination, because many old servers still do not offer it. So TLS there is opportunistic (encrypt if possible, accept any certificate). Two technologies close that gap for your domain:

  • MTA-STS (RFC 8461): você publica uma política em HTTPS (https://mta-sts.seudominio.com/.well-known/mta-sts.txt) e um registro DNS _mta-sts. Quem envia para você passa a exigir TLS válido para os seus MX. Não depende de DNSSEC.MTA-STS (RFC 8461): you publish a policy over HTTPS (https://mta-sts.yourdomain.com/.well-known/mta-sts.txt) and a _mta-sts DNS record. Senders to you then require valid TLS for your MX hosts. It does not depend on DNSSEC.
  • DANE (RFC 7672): você publica o certificado (registros TLSA) no DNS, assinado com DNSSEC. Mais forte, mas exige DNSSEC.DANE (RFC 7672): you publish the certificate (TLSA records) in DNS, signed with DNSSEC. Stronger, but requires DNSSEC.
  • TLS-RPT (RFC 8460): relatórios diários dos remetentes dizendo onde o TLS falhou com você.TLS-RPT (RFC 8460): daily reports from senders saying where TLS failed with you.
# política MTA-STS (arquivo servido em HTTPS)
version: STSv1
mode: enforce          # comece com "testing"
mx: mail.seudominio.com
max_age: 604800

# DNS
_mta-sts.seudominio.com. TXT "v=STSv1; id=20261027T000000"
_smtp._tls.seudominio.com. TXT "v=TLSRPTv1; rua=mailto:tls@seudominio.com"

3.2 Acesso: autenticação3.2 Access: authentication

Na 587/465 o cliente prova quem é com o comando AUTH (RFC 4954). Os mecanismos comuns, PLAIN e LOGIN, mandam a senha só codificada em base64, ou seja, legível. Por isso a regra é: o servidor só oferece AUTH depois do TLS. O laboratório confere: o EHLO do Mailpit, logo após o TLS, anuncia AUTH LOGIN PLAIN.On 587/465 the client proves who it is with the AUTH command (RFC 4954). The common mechanisms, PLAIN and LOGIN, send the password only base64-encoded, which means readable. So the rule is: the server only offers AUTH after TLS. The lab checks it: Mailpit's EHLO, right after TLS, announces AUTH LOGIN PLAIN.

  • Uma credencial por aplicação (senha de app, usuário SMTP dedicado), para revogar uma sem derrubar as outras.One credential per application (app password, dedicated SMTP user), so you can revoke one without breaking the others.
  • OAuth2 (XOAUTH2, OAUTHBEARER) onde o provedor suporta: o app usa um token de curta duração em vez da senha da conta.OAuth2 (XOAUTH2, OAUTHBEARER) where the provider supports it: the app uses a short-lived token instead of the account password.
  • Limite de taxa e bloqueio de tentativas falhas (fail2ban, postscreen), porque a porta 587 é alvo constante de força bruta.Rate limits and blocking of failed attempts (fail2ban, postscreen), because port 587 is a constant brute-force target.
  • Credenciais fora do código: variável de ambiente ou gerenciador de segredos, como nas outras notas.Credentials out of the code: environment variable or secrets manager, as in the other notes.

O caminho seguro é gradual: publique SPF e DKIM, ponha o DMARC em p=none e leia os relatórios agregados por algumas semanas para descobrir todos os serviços que enviam em nome do domínio (marketing, suporte, sistema de cobrança), depois suba para quarantine e por fim reject. Subir direto para reject derruba o e-mail legítimo que você esqueceu. Jumping straight to reject kills legitimate email you forgot about. Since 2024 Google and Yahoo require SPF, DKIM and DMARC from bulk senders to their accounts, so this stopped being optional for an app with real users.

3.4 Operação: não vire um relay aberto3.4 Operation: do not become an open relay

Um open relay é um servidor que aceita e reenvia e-mail de qualquer pessoa para qualquer lugar. Spammers o encontram em horas, e o seu IP vai para listas de bloqueio. A regra é simples: o servidor só aceita mensagens (a) para domínios que ele hospeda, ou (b) de clientes autenticados (ou de redes de confiança explícitas, como um IP interno). Em Postfix, é o papel de smtpd_relay_restrictions:An open relay is a server that accepts and forwards email from anyone to anywhere. Spammers find it within hours, and your IP lands on blocklists. The rule is simple: the server only accepts messages (a) for domains it hosts, or (b) from authenticated clients (or explicit trusted networks, such as an internal IP). In Postfix, that is the job of smtpd_relay_restrictions:

# /etc/postfix/main.cf (trecho)
smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination
smtpd_tls_security_level = may          # porta 25: oportunista
smtpd_tls_auth_only = yes               # AUTH só dentro do TLS
disable_vrfy_command = yes              # não revela quais caixas existem
  • DNS reverso (PTR) do IP de saída apontando para o nome do seu servidor, e o nome resolvendo de volta ao IP. Sem isso, muitos destinos recusam.Reverse DNS (PTR) for the outbound IP pointing to your server's name, and the name resolving back to the IP. Without it, many destinations refuse.
  • Certificado válido (Let's Encrypt) com renovação automática, para o nome que o MX anuncia.A valid certificate (Let's Encrypt) with automatic renewal, for the name the MX announces.
  • Monitore a fila (mailq) e os logs: uma fila crescendo de repente é sinal de conta comprometida enviando spam.Monitor the queue (mailq) and logs: a suddenly growing queue is a sign of a compromised account sending spam.
  • Mantenha atualizado: servidores de e-mail ficam expostos à internet e já tiveram falhas graves (por exemplo, a smuggling de SMTP de 2023, em que terminadores de DATA ambíguos permitiam forjar mensagens).Keep it patched: mail servers are exposed to the internet and have had serious flaws (for example, the 2023 SMTP smuggling, where ambiguous DATA terminators let attackers forge messages).
Recomendação prática, e opinião minha: para um app, não opere o seu próprio MTA de saída. Use um serviço de relay (SES, Postmark, Mailgun, Resend), que já cuida de reputação de IP, PTR e filas, e configure só SPF, DKIM e DMARC no seu domínio. Operar o servidor completo é ótimo para aprender (seção 4) e razoável para caixa de e-mail própria, mas entregabilidade é um trabalho contínuo.Practical recommendation, and my opinion: for an app, do not run your own outbound MTA. Use a relay service (SES, Postmark, Mailgun, Resend), which already handles IP reputation, PTR and queues, and configure only SPF, DKIM and DMARC on your domain. Running the full server is great for learning (section 4) and reasonable for your own mailbox, but deliverability is ongoing work.
TLS não é ponta a ponta. Mesmo com tudo acima, cada servidor do caminho lê a mensagem em claro. Para o conteúdo ficar secreto até o leitor é preciso criptografar a própria mensagem (S/MIME ou OpenPGP), o que está fora do escopo desta nota.TLS is not end to end. Even with everything above, every server on the path reads the message in the clear. To keep the content secret until the reader you must encrypt the message itself (S/MIME or OpenPGP), which is outside this note's scope.

send.py (cliente seguro: confia só no nosso certificado, faz STARTTLS e depois login):send.py (secure client: trusts only our certificate, does STARTTLS and then login):

import smtplib, ssl, sys
from email.message import EmailMessage

msg = EmailMessage()
msg["From"] = "ana@example.com"
msg["To"] = "bruno@example.org"
msg["Subject"] = "Olá pelo SMTP"
msg.set_content("Corpo da mensagem.\n")

ctx = ssl.create_default_context(cafile="certs/cert.pem")   # confia só no nosso certificado
with smtplib.SMTP("localhost", 1025) as s:
    s.starttls(context=ctx)
    s.login("ana", sys.argv[1])
    s.send_message(msg)
print("enviado")

O teste 1 é a defesa contra o downgrade da seção 3.1 em ação, o 2 mostra o 535 e o 3 mostra o caminho feliz. Sem o cafile, o Python recusaria o certificado autoassinado: é a verificação de certificado funcionando, e o motivo de nunca desligá-la (CERT_NONE) para "fazer funcionar".Test 1 is the section 3.1 downgrade defence in action, 2 shows the 535 and 3 shows the happy path. Without the cafile, Python would refuse the self-signed certificate: that is certificate verification working, and the reason never to turn it off (CERT_NONE) just to "make it work".

Só no laboratório. O certificado autoassinado e a senha "segredo" são para teste. Em produção use um certificado de uma CA (Let's Encrypt) e segredos de verdade. 6. Checklist6. Checklist

  • Aplicação envia pela 587 (STARTTLS) ou 465 (TLS implícito), autenticada, com TLS obrigatório e certificado verificado.The application sends via 587 (STARTTLS) or 465 (implicit TLS), authenticated, with TLS required and the certificate verified.
  • Uma credencial por aplicação, fora do código, revogável.One credential per application, out of the code, revocable.
  • Servidor oferece AUTH só depois do TLS; relay fechado (reject_unauth_destination); VRFY desligado.Server offers AUTH only after TLS; relay closed (reject_unauth_destination); VRFY off.
  • SPF, DKIM e DMARC publicados; DMARC começa em p=none e sobe com base nos relatórios.SPF, DKIM and DMARC published; DMARC starts at p=none and rises based on the reports.
  • MTA-STS (e TLS-RPT) no domínio que recebe e-mail; DANE se você já tem DNSSEC.MTA-STS (and TLS-RPT) on the domain that receives email; DANE if you already have DNSSEC.
  • PTR do IP de saída, certificado válido com renovação, fila e logs monitorados, software atualizado.PTR for the outbound IP, valid certificate with renewal, queue and logs monitored, software patched.
  • Em desenvolvimento, use uma caixa de areia (Mailpit); nunca aponte testes para um relay real com endereços de clientes.In development, use a sandbox (Mailpit); never point tests at a real relay with customers' addresses.
  • Para um app, prefira um serviço de relay a operar o próprio MTA.For an app, prefer a relay service to running your own MTA.
