SEO, GEO e o exemplo usado aquiSEO, GEO and the example used here

SEO (otimização para mecanismos de busca) é tornar o site fácil de rastrear, entender e exibir no Google, Bing e similares. GEO (otimização para mecanismos generativos) é o mesmo esforço para que ChatGPT, Claude, Perplexity e Gemini consigam ler o site e citá-lo ao responder. As duas coisas se apoiam no mesmo alicerce: HTML claro, URLs estáveis, dados estruturados e permissão explícita para os rastreadores.SEO (search engine optimisation) is making a site easy to crawl, understand and display in Google, Bing and the like. GEO (generative engine optimisation) is the same effort so that ChatGPT, Claude, Perplexity and Gemini can read the site and cite it when answering. Both rest on the same foundation: clear HTML, stable URLs, structured data and explicit permission for crawlers.

O exemplo desta nota é o setup de SEO de um site fictício, a Arcada Software (landing pages e sites institucionais), em português e inglês, hospedado na Cloudflare Pages. O domínio arcada.example é reservado para exemplos e não existe de verdade; troque pelo seu. Cada seção mostra o arquivo, explica cada linha e diz o que ele não faz.The example in this note is the SEO setup of a fictional site, Arcada Software (landing pages and business websites), in Portuguese and English, hosted on Cloudflare Pages. The domain arcada.example is reserved for examples and does not really exist; swap in yours. Each section shows the file, explains each line and says what it does not do.

Sem garantia de posição: nenhuma tag faz o site subir ao topo. Elas tiram obstáculos (página que o rastreador não acha, duplicada ou mal interpretada). Quem decide a posição é a relevância e a qualidade do conteúdo, e o tempo.No ranking guarantee: no tag pushes a site to the top. They remove obstacles (a page the crawler cannot find, duplicated or misread). Position is decided by content relevance and quality, and by time.

Open Graph (og:*) controla a pré-visualização quando alguém cola o link no WhatsApp, LinkedIn, Facebook, Slack ou iMessage. Os Twitter Cards fazem o mesmo no X. Não ajudam no ranking, mas decidem se o link compartilhado parece confiável.Open Graph (og:*) controls the preview when someone pastes the link into WhatsApp, LinkedIn, Facebook, Slack or iMessage. Twitter Cards do the same on X. They do not help ranking, but they decide whether a shared link looks trustworthy.

Dois idiomas: hreflangTwo languages: hreflang

<link rel="alternate" hreflang="pt-BR" href="https://arcada.example/">
<link rel="alternate" hreflang="en" href="https://arcada.example/en/">
<link rel="alternate" hreflang="x-default" href="https://arcada.example/">

hreflang diz ao buscador que as duas URLs são o mesmo conteúdo em idiomas diferentes, para mostrar a versão certa a cada pessoa em vez de tratá-las como duplicatas. Regras que costumam dar erro:hreflang tells the search engine the two URLs are the same content in different languages, so it shows each person the right version instead of treating them as duplicates. Rules that commonly go wrong:

  • Recíproco: a página PT lista a EN e a EN lista a PT. Sem a volta, o Google ignora o par.Reciprocal: the PT page lists the EN one and the EN lists the PT. Without the return link, Google ignores the pair.
  • Inclua a própria página na lista (a PT lista pt-BR apontando para si).Include the page itself in the list (PT lists pt-BR pointing at itself).
  • x-default é a versão para quem não casa com nenhum idioma listado; aqui, o português.x-default is the version for people who match none of the listed languages; here, Portuguese.
  • O canonical de cada versão aponta para ela mesma, nunca para a outra. Apontar o canonical da EN para a PT diria ao Google que a EN é cópia e a tiraria do índice.The canonical of each version points to itself, never to the other. Pointing the EN canonical at the PT page would tell Google the EN is a copy and drop it from the index.
  • Os mesmos três links aparecem também no sitemap (veja abaixo); basta manter um dos dois lugares coerente com o outro.The same three links also appear in the sitemap (see below); just keep the two places consistent with each other.

Dados estruturados: JSON-LDStructured data: JSON-LD

O HTML descreve como a página aparece; o JSON-LD descreve o que ela é em um vocabulário que máquinas entendem (schema.org). Fica num bloco <script type="application/ld+json">, e como é dado, não executa nada e não precisa de exceção na CSP. Um bloco só, com @graph, liga as entidades por @id:HTML describes how the page looks; JSON-LD describes what it is in a vocabulary machines understand (schema.org). It lives in a <script type="application/ld+json"> block, and being data, it runs nothing and needs no CSP exception. A single block with @graph links the entities by @id:

<script type="application/ld+json">
{

      "@id": "https://arcada.example/#org",
      "name": "Arcada Software",
      "url": "https://arcada.example/",
      "logo": {

        "url": "https://arcada.example/icon-512.png",
        "width": 512,
        "height": 512
      },
      "description": "Landing pages, sites institucionais e pequenos projetos web.",
      "email": "contato@arcada.example",
      "areaServed": "BR",
      "availableLanguage": ["pt-BR", "en"],
      "knowsAbout": ["landing pages", "sites institucionais", "desenvolvimento web", "SEO técnico"]
    },
    {
      "@type": "WebSite",
      "@id": "https://arcada.example/#site",
      "url": "https://arcada.example/",
      "name": "Arcada Software",
      "inLanguage": "pt-BR",
      "publisher": { "@id": "https://arcada.example/#org" }
    },
    {
      "@type": "WebPage",
      "@id": "https://arcada.example/#page",
      "url": "https://arcada.example/",

      "inLanguage": "pt-BR",
      "isPartOf": { "@id": "https://arcada.example/#site" },

Do not use AggregateRating, Review, LocalBusiness, Product, HowTo or Speakable if that data is not on screen. Marking up reviews that do not exist violates Google's guidelines and can bring a manual action against the site.

robots.txt e rastreadores de IArobots.txt and AI crawlers

O robots.txt fica na raiz (/robots.txt) e diz a cada rastreador o que ele pode buscar. É um pedido de boa-fé, não uma barreira: bots de bem obedecem; bots maliciosos ignoram. Nunca use o robots.txt para esconder algo secreto (ele próprio é público) e nunca para proteger dados: para isso use autenticação.The robots.txt sits at the root (/robots.txt) and tells each crawler what it may fetch. It is a good-faith request, not a barrier: well-behaved bots obey; malicious ones ignore it. Never use robots.txt to hide something secret (the file itself is public) and never to protect data: use authentication for that.
