O que éWhat it is

Hermes Agent é um agente de IA open-source (licença MIT) da Nous Research, que o descreve como "o agente que se melhora sozinho". Na prática é um programa que você instala, aponta para um modelo de linguagem (LLM) e conversa com ele pelo terminal ou pelo celular, via Telegram, WhatsApp, Signal e outros. Ele executa comandos, edita arquivos, pesquisa na web, agenda tarefas e, o que o distingue, guarda memória entre conversas e transforma o que aprendeu em skills reutilizáveis.Hermes Agent is an open-source AI agent (MIT license) from Nous Research, which describes it as "the self-improving agent". In practice it is a program you install, point at a large language model (LLM) and talk to from the terminal or from your phone, via Telegram, WhatsApp, Signal and others. It runs commands, edits files, searches the web, schedules tasks and, what sets it apart, keeps memory across conversations and turns what it learned into reusable skills.

Não confunda o agente com os modelos. "Hermes" também é uma família de modelos da Nous (Hermes 3, Hermes 4). O Hermes Agent é o programa em volta do modelo e funciona com qualquer LLM que você configurar (seção 6). A nota sobre harness de agentes explica o que é essa camada; aqui vemos um exemplo completo dela.Do not confuse the agent with the models. "Hermes" is also a family of Nous models (Hermes 3, Hermes 4). Hermes Agent is the program around the model and works with any LLM you configure (section 6). The agent harness note explains what that layer is; here we see a complete example of it.

O coração dela é um loop de agente, o mesmo padrão de qualquer agente com ferramentas:All entry points (the cli.py terminal, the gateway/run.py gateway, the editor integration, the API) end up in the same class, AIAgent. 2. Memória2. Memory

Um LLM não lembra de nada entre chamadas; tudo o que ele "sabe" numa conversa está no prompt. A memória do Hermes é um conjunto de arquivos e um banco que ele escreve e relê, em três camadas:An LLM remembers nothing between calls; everything it "knows" in a conversation is in the prompt. Hermes's memory is a set of files and a database that it writes and rereads, in three layers:

Camada 1: MEMORY.md e USER.mdLayer 1: MEMORY.md and USER.md

  • Ficam em ~/.hermes/memories/. O MEMORY.md guarda fatos do ambiente, convenções e lições (limite de 2.200 caracteres, uns 800 tokens); o USER.md guarda suas preferências e estilo (1.375 caracteres).They live in ~/.hermes/memories/. MEMORY.md holds environment facts, conventions and lessons (limit 2,200 characters, about 800 tokens); USER.md holds your preferences and style (1,375 characters).
  • O agente escreve com a ferramenta memory (ações add, patch e remove; não há "ler", porque o conteúdo já está no prompt). Quando estoura o limite, a ferramenta devolve erro e o agente precisa reorganizar: nada é apagado sozinho.The agent writes with the memory tool (actions add, patch and remove; there is no "read", because the content is already in the prompt). When the limit is exceeded the tool returns an error and the agent must reorganize: nothing is deleted by itself.
  • Instantâneo congelado: o conteúdo é carregado no prompt no começo da sessão. O que o agente escreve durante a sessão vai para o disco na hora, mas só aparece no prompt na próxima sessão. Isso mantém o prefixo do prompt estável e o cache do provedor funcionando.Frozen snapshot: the content is loaded into the prompt at session start. What the agent writes mid-session goes to disk immediately but only appears in the prompt in the next session. This keeps the prompt prefix stable and the provider's cache working.
  • Cada escrita é varrida em busca de padrões de injeção de prompt e exfiltração, e de caracteres Unicode invisíveis, que são bloqueados. Faz sentido: uma página web maliciosa não deve conseguir plantar uma "lembrança" que valha para sempre.Each write is scanned for prompt-injection and exfiltration patterns, and invisible Unicode characters, which are blocked. This makes sense: a malicious web page should not be able to plant a "memory" that lasts forever.
  • Para revisar antes de gravar, ligue memory.write_approval: true: as escritas ficam pendentes e você usa /memory pending, /memory approve e /memory reject.To review before saving, turn on memory.write_approval: true: writes stay pending and you use /memory pending, /memory approve and /memory reject.
# ~/.hermes/config.yaml (trecho da documentação)
memory:
  memory_enabled: true
  user_profile_enabled: true
  memory_char_limit: 2200
  user_char_limit: 1375
  write_approval: false      # true = você aprova cada escrita
skills:
  write_approval: false      # idem para skills (seção 3)

Camada 2: o histórico de sessõesLayer 2: session history

Toda conversa, do terminal ou de qualquer app, é gravada em ~/.hermes/state.db (SQLite) com busca de texto FTS5. Quando você pergunta "o que decidimos sobre o deploy semana passada?", o agente busca ali e recebe as mensagens originais, sem resumo no meio. Você também lista as sessões com hermes sessions list. Como é um banco e não o prompt, ele cresce sem custo de contexto.Every conversation, from the terminal or any app, is written to ~/.hermes/state.db (SQLite) with FTS5 full-text search. When you ask "what did we decide about the deploy last week?", the agent searches there and receives the original messages, with no summary in between. You can also list sessions with hermes sessions list. Because it is a database and not the prompt, it grows at no context cost.

Camada 3: provedores externosLayer 3: external providers

Plugins como Honcho (que monta um modelo de você ao longo do tempo), Mem0, Hindsight e Supermemory rodam ao lado das camadas 1 e 2, sem substituí-las. Configure com hermes memory setup e veja o estado com hermes memory status.Plugins such as Honcho (which builds a model of you over time), Mem0, Hindsight and Supermemory run alongside layers 1 and 2, without replacing them. Set up with hermes memory setup and check with hermes memory status.

Uma memória por casa. A memória é por perfil (hermes -p work usa ~/.hermes/profiles/work/). A documentação avisa para nunca apontar dois processos do agente para o mesmo diretório do Hermes: dois gateways gravando no mesmo state.db é pedir problema.One memory per home. Memory is per profile (hermes -p work uses ~/.hermes/profiles/work/). The documentation warns never to point two agent processes at the same Hermes directory: two gateways writing to the same state.db is asking for trouble.

3. Skills que ele mesmo cria3. Skills it creates itself

Uma skill é uma pasta com um arquivo SKILL.md (frontmatter YAML + instruções em Markdown) que ensina o agente a fazer uma tarefa. O formato segue o padrão aberto agentskills.io, o mesmo das Agent Skills da nota de harness. A diferença do Hermes é que ele escreve as próprias skills: o prompt do sistema pede que ele salve fluxos que valem repetir.A skill is a folder with a SKILL.md file (YAML frontmatter + Markdown instructions) that teaches the agent a task. The format follows the open agentskills.io standard, the same as the Agent Skills in the harness note. What is different in Hermes is that it writes its own skills: the system prompt asks it to save workflows worth repeating.

# ~/.hermes/skills/devops/deploy-site/SKILL.md  (exemplo, no formato da documentação)
---
name: deploy-site
description: Publica o site estático no servidor e confere se subiu
version: 1.0.0
platforms: [linux]
metadata:
  hermes:
    tags: [deploy]
    category: devops
    requires_toolsets: [terminal]
---

4. Telegram, WhatsApp, Signal e o resto4. Telegram, WhatsApp, Signal and the rest

O gateway é um processo em segundo plano que se conecta a todos os apps configurados. Cada app tem um adaptador que recebe as mensagens, e todas passam por uma sessão por conversa e chegam ao mesmo agente. Por isso a mesma memória e as mesmas skills valem no celular e no terminal. As plataformas da documentação:The gateway is a background process that connects to all configured apps. Each app has an adapter that receives messages, and all of them go through one session per conversation and reach the same agent. That is why the same memory and skills apply on the phone and in the terminal. The platforms in the documentation:

A configuração é guiada: hermes gateway setup pergunta qual plataforma você quer e pede os dados. Os três apps que você citou:Setup is guided: hermes gateway setup asks which platform you want and requests the details. The three apps you mentioned:

Telegram

  1. No Telegram, abra o @BotFather, envie /newbot, escolha um nome e um usuário que termine em bot. Ele devolve o token (segredo: se vazar, /revoke).In Telegram, open @BotFather, send /newbot, choose a name and a username ending in bot. It returns the token (secret: if it leaks, /revoke).

O Telegram é o melhor para um servidor: por padrão o gateway usa polling (ele pergunta ao Telegram se há mensagens), ou seja, só conexões de saída. Não precisa abrir porta nem ter domínio. O modo webhook (TELEGRAM_WEBHOOK_URL) existe para plataformas que acordam a máquina com tráfego de entrada.Telegram is the best fit for a server: by default the gateway uses polling (it asks Telegram whether there are messages), meaning outbound connections only. No need to open a port or own a domain. Webhook mode (TELEGRAM_WEBHOOK_URL) exists for platforms that wake the machine on inbound traffic.

WhatsApp

Há dois caminhos. A ponte Baileys (hermes whatsapp) emula uma sessão do WhatsApp Web: você escaneia um QR code em Configurações → Dispositivos conectados, não precisa de conta Meta nem de URL pública, mas tem risco de banimento, porque o WhatsApp não suporta bots de terceiros fora da API oficial. A Cloud API (oficial, da Meta) evita esse risco, mas exige conta Business e um webhook público.There are two paths. The Baileys bridge (hermes whatsapp) emulates a WhatsApp Web session: you scan a QR code in Settings → Linked Devices, need no Meta account or public URL, but it carries a ban risk, because WhatsApp does not support third-party bots outside the official API. Signal

O Signal depende de um programa separado, o signal-cli (precisa de Java 17+), que roda como serviço local e que o Hermes acessa por HTTP. Você vincula o signal-cli ao seu número como aparelho secundário e deixa o daemon rodando:Signal depends on a separate program, signal-cli (needs Java 17+), which runs as a local service that Hermes reaches over HTTP. Quem pode falar com o bot: pareamento de DMWho can talk to the bot: DM pairing

Um bot de chat é público por natureza: qualquer um que achar o nome pode mandar mensagem, e esse bot executa comandos. Por isso o gateway nega por padrão. Há duas formas de liberar alguém: uma lista (TELEGRAM_ALLOWED_USERS, WHATSAPP_ALLOWED_USERS, GATEWAY_ALLOWED_USERS...) ou o pareamento: um desconhecido manda mensagem, o bot responde com um código de 8 caracteres, e você, no servidor, aprova:A chat bot is public by nature: anyone who finds the name can message it, and this bot runs commands. So the gateway denies by default. There are two ways to let someone in: a list (TELEGRAM_ALLOWED_USERS, WHATSAPP_ALLOWED_USERS, GATEWAY_ALLOWED_USERS...) or pairing: a stranger messages, the bot replies with an 8-character code, and you, on the server, approve:

hermes pairing list
hermes pairing approve telegram XKGH5N7P
hermes pairing revoke telegram 123456789

Dá para separar administradores de usuários comuns por plataforma (allow_admin_from, user_allowed_commands), e o /whoami mostra o seu nível. Outras coisas úteis do gateway: se um adaptador falha várias vezes, um circuit breaker o pausa (retome com /platform resume <nome>); um watchdog encerra o processo se o loop travar, para o supervisor reiniciá-lo; e as respostas finais ficam num registro no state.db e são reenviadas após uma queda.You can split admins from regular users per platform (allow_admin_from, user_allowed_commands), and /whoami shows your tier. Other useful gateway behaviours: if an adapter fails repeatedly, a circuit breaker pauses it (resume with /platform resume <name>); a watchdog exits the process if the loop stalls, so the supervisor restarts it; and final replies are kept in a ledger in state.db and resent after a crash.

5. Guardrails5. Guardrails

Um agente que executa comandos a partir de mensagens de chat é, por definição, perigoso: um erro do modelo, um texto malicioso numa página que ele leu ou um desconhecido no bot podem virar um rm -rf. A documentação descreve oito camadas. As que mais importam:An agent that runs commands from chat messages is dangerous by definition: a model mistake, malicious text on a page it read or a stranger on the bot can become an rm -rf. The documentation describes eight layers. The ones that matter most:

Aprovação de comandosCommand approval

Em ~/.hermes/config.yaml, a chave approvals.mode tem três valores: smart (padrão: um modelo auxiliar avalia o risco; baixo risco passa, perigoso é negado, incerto vira pergunta para você), manual (sempre pergunta) e off (equivale ao modo --yolo). Comandos que disparam a aprovação incluem rm recursivo, chmod 777, DROP/TRUNCATE, curl | sh, kill -9, escritas em /etc/ e em ~/.ssh/. No chat você responde yes ou no; no terminal, once, session, always ou deny. Se você não responder em approvals.timeout (300 s por padrão), o pedido é negado.In ~/.hermes/config.yaml, the approvals.mode key has three values: smart (default: an auxiliary model rates the risk; low risk passes, dangerous is denied, uncertain becomes a question to you), manual (always asks) and off (same as --yolo). Commands that trigger approval include recursive rm, chmod 777, DROP/TRUNCATE, curl | sh, kill -9, writes to /etc/ and ~/.ssh/. In chat you answer yes or no; in the terminal, once, session, always or deny. If you do not answer within approvals.timeout (300 s by default), the request is denied.

# ~/.hermes/config.yaml
approvals:
  mode: manual            # para um servidor exposto, comece com "manual"
  timeout: 300
  cron_mode: deny         # tarefas agendadas sem ninguém para aprovar: negar
  deny:                   # regras suas, avaliadas antes de qualquer modo
    - "rm -rf *"
    - "*curl*|*sh*"

Dois detalhes importantes. Primeiro, há uma lista negra fixa (rm -rf /, fork bomb, mkfs no disco raiz, dd sobre disco) que vale até no modo --yolo. Segundo, tarefas sem ninguém por perto (agendadas, webhooks) usam cron_mode, unattended_mode etc., todos deny por padrão: um comando perigoso numa tarefa das 3h da manhã é negado, não executado.Two important details. First, there is a fixed blocklist (rm -rf /, fork bomb, mkfs on the root disk, dd over a disk) that applies even in --yolo mode. Second, tasks with nobody around (scheduled, webhooks) use cron_mode, unattended_mode etc., all deny by default: a dangerous command in a 3am task is denied, not run.

Escrita de arquivos, segredos e injeção de promptFile writes, secrets and prompt injection

  • Escrita: as ferramentas write_file e patch não gravam em ~/.ssh/, ~/.aws/, ~/.kube/, /etc/sudoers nem nos segredos do próprio Hermes (.env, vault/, pairing/), sem pedir aprovação.Writes: the write_file and patch tools do not write to ~/.ssh/, ~/.aws/, ~/.kube/, /etc/sudoers nor Hermes's own secrets (.env, vault/, pairing/), without asking for approval.
  • Segredos: o execute_code remove variáveis com KEY, TOKEN, SECRET, PASSWORD no nome; o backend Docker e o SSH não herdam variáveis do host; processos MCP só recebem variáveis seguras mais as que você declara; e erros de MCP têm tokens (ghp_, sk-, Bearer) trocados por [REDACTED] antes de chegar ao LLM.Secrets: execute_code strips variables with KEY, TOKEN, SECRET, PASSWORD in the name; the Docker and SSH backends do not inherit host variables; MCP processes only get safe variables plus the ones you declare; and MCP errors have tokens (ghp_, sk-, Bearer) replaced with [REDACTED] before reaching the LLM.
  • Injeção de prompt: AGENTS.md, .cursorrules e SOUL.md são varridos (instruções do tipo "ignore as anteriores", comentários HTML escondidos, tentativas de ler .env, exfiltração por curl, Unicode invisível) e bloqueados se suspeitos. Comandos que enviam segredos por curl são sinalizados.Prompt injection: AGENTS.md, .cursorrules and SOUL.md are scanned ("ignore previous instructions", hidden HTML comments, attempts to read .env, curl exfiltration, invisible Unicode) and blocked if suspicious. Commands that send secrets via curl are flagged.
  • Rede: a proteção SSRF bloqueia endereços privados, loopback e o endpoint de metadados da nuvem (169.254.169.254) nas ferramentas de URL, e há uma lista de domínios proibidos (security.website_blocklist). Isso importa na AWS: sem ela, uma página maliciosa poderia induzir o agente a ler as credenciais da instância.Network: SSRF protection blocks private addresses, loopback and the cloud metadata endpoint (169.254.169.254) in URL tools, and there is a domain blocklist (security.website_blocklist). This matters on AWS: without it, a malicious page could trick the agent into reading the instance credentials.

Onde roda: a única fronteira de verdadeWhere it runs: the only real boundary

O backend de terminal local executa os comandos como o seu usuário, sem isolamento. Os backends de contêiner (docker, Modal, Daytona...) isolam de verdade: no Docker, o Hermes usa --cap-drop ALL, no-new-privileges, limite de processos (256) e /tmp em memória, com limites de CPU, memória e disco configuráveis. Nesses backends a verificação de comandos perigosos é dispensada, porque o contêiner é a fronteira. A documentação lista o que fazer em produção:The local terminal backend runs commands as your user, with no isolation. The container backends (docker, Modal, Daytona...) isolate for real: with Docker, Hermes uses --cap-drop ALL, no-new-privileges, a process limit (256) and an in-memory /tmp, with configurable CPU, memory and disk limits. On those backends the dangerous-command check is skipped, because the container is the boundary. The documentation lists what to do in production:

  • Allowlists explícitas; evite GATEWAY_ALLOW_ALL_USERS=true; use pareamento onde der.Explicit allowlists; avoid GATEWAY_ALLOW_ALL_USERS=true; use pairing where possible.
  • Backend de contêiner, com limites de CPU, memória e disco.A container backend, with CPU, memory and disk limits.
  • Segredos em ~/.hermes/.env com chmod 600; terminal.cwd numa pasta sem nada sensível.Secrets in ~/.hermes/.env with chmod 600; terminal.cwd in a folder with nothing sensitive.
  • Não rodar o gateway como root; auditar o command_allowlist; olhar ~/.hermes/logs/; rodar hermes update com frequência.Do not run the gateway as root; audit the command_allowlist; watch ~/.hermes/logs/; run hermes update often.
Aviso sobre o --yolo. Ele desliga as aprovações para a sessão. Num bot que atende o celular, nunca o deixe ligado de forma permanente. Como o modo smart usa outro LLM para julgar risco, ele reduz o ruído, mas não é garantia: para um agente exposto à internet, comece em manual.Warning about --yolo. It turns off approvals for the session. On a bot serving your phone, never leave it permanently on. Because smart mode uses another LLM to judge risk, it reduces noise but is no guarantee: for an agent exposed to the internet, start with manual.
Nota pessoal, não verificada nas fontes: a conclusão de que "só o contêiner é fronteira de verdade" é minha leitura da própria documentação (que chama a lista de negação de "guarda-corpo, não sandbox"). Ligue isto à nota de harness e guardrails (a "trifeta letal": dados privados + conteúdo não confiável + comunicação externa): um agente com memória, web e shell tem as três.Personal note, not verified in the sources: the conclusion that "only the container is a real boundary" is my reading of the documentation itself (which calls the denylist a "guardrail, not a sandbox"). Tie this to the harness and guardrails note (the "lethal trifecta": private data + untrusted content + external communication): an agent with memory, web and shell has all three.
