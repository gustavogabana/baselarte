A Anthropic, no guia Building effective agents, define a diferença com precisão: em um workflow, o código decide a ordem dos passos; em um agente, é o próprio modelo que decide os próximos passos e quais ferramentas usar, usando o retorno do ambiente em um laço. O mesmo guia dá um conselho valioso: comece com a solução mais simples possível; muitas vezes, uma única chamada ao modelo já basta.Anthropic, in the guide Building effective agents, defines the difference precisely: in a workflow, code decides the order of the steps; in an agent, the model itself decides the next steps and which tools to use, using feedback from the environment in a loop. The same guide gives valuable advice: start with the simplest solution possible; often a single call to the model is enough.

Por que open-source? Três razões práticas: privacidade (os dados não saem da sua máquina), custo previsível (sem cobrança por token) e controle (você escolhe a versão e ela não muda sozinha). O preço é que você cuida do hardware e os melhores modelos fechados costumam ser mais capazes.Why open-source? Three practical reasons: privacy (data never leaves your machine), predictable cost (no per-token billing) and control (you pick the version and it does not change on its own). The price is that you look after the hardware, and the best closed models are usually more capable.

Cabe na minha máquina? A conta da memóriaWill it fit on my machine? The memory maths

Um modelo é medido em parâmetros (os números dentro do arquivo). “8B” significa 8 bilhões. Cada parâmetro ocupa alguns bits, e quantos bits depende da quantização: reduzir a precisão dos números (de 16 bits para 8 ou 4) para o modelo ocupar menos memória, com uma perda pequena de qualidade. Pesquisa de Dettmers e Zettlemoyer (2022) mostra que, para uma mesma memória, modelos maiores quantizados em 4 bits tendem a superar modelos menores em precisão maior, e por isso 4 bits virou o padrão no uso local.A model is measured in parameters (the numbers inside the file). “8B” means 8 billion. Each parameter takes a few bits, and how many depends on quantization: lowering the precision of the numbers (from 16 bits to 8 or 4) so the model takes less memory, with a small loss of quality. Research by Dettmers and Zettlemoyer (2022) shows that, for the same memory, larger models quantized to 4 bits tend to beat smaller models at higher precision, which is why 4 bits became the default for local use.

A regra de bolso: memória dos pesos ≈ parâmetros × bits ÷ 8. Some ainda 1 a 3 GB de folga para o contexto (o “cache KV”, que cresce com o tamanho da conversa) e para o sistema.The rule of thumb: weights memory ≈ parameters × bits ÷ 8. Add 1 to 3 GB of headroom for the context (the “KV cache”, which grows with conversation length) and for the system.

def gb(params_billion, bits):
    return params_billion * bits / 8

MoE (mixture of experts) explica os números enormes. O modelo é dividido em “especialistas” e, a cada token, só alguns são usados: o Kimi K2 tem ~1T de parâmetros no total, mas só 32B ativos por token. O que isso muda na conta da memória: a velocidade acompanha os parâmetros ativos, mas a memória acompanha os totais, porque todos os especialistas precisam estar carregados. Por isso um MoE é rápido para o tamanho, e ainda assim exige muita VRAM.MoE (mixture of experts) explains the huge numbers. The model is split into “experts” and, for each token, only a few are used: Kimi K2 has ~1T parameters in total but only 32B active per token. What it changes in the memory maths: speed follows the active parameters, but memory follows the total, because every expert has to be loaded. That is why a MoE is fast for its size and still demands a lot of VRAM.

Três cuidados. (1) Pesos abertos não é o mesmo que open-source no sentido estrito: em geral o código e os dados de treino não são publicados, e a licença varia por modelo e por versão. Leia a licença no cartão do modelo no Hugging Face antes de usar comercialmente. (2) Rodar os pesos na sua máquina não envia dados a ninguém; já usar a API hospedada do laboratório (por exemplo, a do DeepSeek) envia o seu texto aos servidores dele, sob a legislação do país dele. (3) Modelos treinados na China costumam recusar ou enviesar respostas sobre alguns temas políticos; teste com o seu caso de uso.Three cautions. (1) Open weights is not the same as open source in the strict sense: usually the code and training data are not published, and the license varies by model and version. Read the license on the model card on Hugging Face before commercial use. (2) Running the weights on your machine sends data to nobody; using the lab’s hosted API (for example DeepSeek’s) sends your text to their servers, under their country’s laws. (3) Models trained in China often refuse or skew answers on some political topics; test with your own use case.

Seu primeiro agente: um laço de 70 linhasYour first agent: a 70-line loop

Um agente parece mágico até você ver o código. O truque se chama chamada de ferramentas (tool calling): junto com a pergunta, você descreve funções que o modelo pode pedir. Se ele quiser usar uma, em vez de texto ele devolve um tool_calls com o nome da função e os argumentos. Quem executa é o seu código, não o modelo; o resultado volta como uma mensagem role: "tool", e o modelo continua. A ideia combina raciocínio e ação em passos alternados, como no artigo ReAct (Yao et al., 2022).An agent feels like magic until you see the code. The trick is called tool calling: along with the question, you describe functions the model may ask for. If it wants one, instead of text it returns a tool_calls with the function name and arguments. Your code runs it, not the model; the result goes back as a role: "tool" message, and the model continues. The idea mixes reasoning and acting in alternating steps, as in the ReAct paper (Yao et al., 2022).

Atividade 5: escreva e rode o agenteActivity 5: write and run the agent

Só usa a biblioteca padrão do Python (3.9 ou mais novo). Duas ferramentas: calc (faz contas sem usar eval) e read_file (lê arquivos, mas só dentro da pasta workspace). Salve como agent.py.It uses only the Python standard library (3.9 or newer). Two tools: calc (does maths without using eval) and read_file (reads files, but only inside the workspace folder). Save it as agent.py.

agent.py

import ast, json, operator, os, sys, urllib.request

BASE_URL = os.environ.get("LLM_BASE_URL", "http://localhost:11434/v1")
MODEL = os.environ.get("LLM_MODEL", "qwen3:8b")
API_KEY = os.environ.get("LLM_API_KEY", "not-needed")
WORKDIR = os.path.abspath("workspace")
MAX_STEPS = 6

# ---- tools: plain Python functions -------------------------------------
OPS = {ast.Add: operator.add, ast.Sub: operator.sub, ast.Mult: operator.mul,
       ast.Div: operator.truediv, ast.Pow: operator.pow, ast.USub: operator.neg}

def calc(expression):
    def ev(n):
        if isinstance(n, ast.Constant) and isinstance(n.value, (int, float)):
            return n.value
        if isinstance(n, ast.BinOp) and type(n.op) in OPS:
            return OPS[type(n.op)](ev(n.left), ev(n.right))
        if isinstance(n, ast.UnaryOp) and type(n.op) in OPS:
            return OPS[type(n.op)](ev(n.operand))
        raise ValueError("only numbers and + - * / ** are allowed")
    return str(ev(ast.parse(expression, mode="eval").body))

def read_file(path):
    full = os.path.abspath(os.path.join(WORKDIR, path))
    if not full.startswith(WORKDIR + os.sep):          # never leave the workspace
        raise ValueError("path outside workspace")
    with open(full, encoding="utf-8") as f:
        return f.read()[:4000]                          # cap what goes back to the model

TOOLS = {"calc": calc, "read_file": read_file}
SCHEMAS = [
    {"type": "function", "function": {
        "name": "calc", "description": "Evaluate an arithmetic expression, e.g. 12*(3+4)",
        "parameters": {"type": "object", "required": ["expression"],
                       "properties": {"expression": {"type": "string"}}}}},
    {"type": "function", "function": {
        "name": "read_file", "description": "Read a text file from the workspace folder",
        "parameters": {"type": "object", "required": ["path"],
                       "properties": {"path": {"type": "string"}}}}},
]

# ---- the model call: one HTTP POST ---------------------------------------
def chat(messages):
    body = json.dumps({"model": MODEL, "messages": messages, "tools": SCHEMAS}).encode()
    req = urllib.request.Request(f"{BASE_URL}/chat/completions", data=body, headers={
        "Content-Type": "application/json", "Authorization": f"Bearer {API_KEY}"})
    with urllib.request.urlopen(req, timeout=300) as resp:
        return json.load(resp)["choices"][0]["message"]

# ---- the agent loop --------------------------------------------------------
def run(task):
    messages = [{"role": "system", "content": "You are a careful assistant. Use tools when needed."},
                {"role": "user", "content": task}]
    for step in range(1, MAX_STEPS + 1):
        msg = chat(messages)
        messages.append(msg)
        calls = msg.get("tool_calls") or []
        if not calls:                                   # no tool requested: this is the answer
            return msg["content"]
        for call in calls:
            name = call["function"]["name"]
            args = json.loads(call["function"]["arguments"])
            print(f"[step {step}] {name}({args})", file=sys.stderr)
            try:
                result = TOOLS[name](**args)
            except Exception as e:                      # give the error back so the model can recover
                result = f"error: {e}"
            messages.append({"role": "tool", "tool_call_id": call["id"], "content": result})
    return "stopped: step limit reached"

if __name__ == "__main__":
    print(run(" ".join(sys.argv[1:]) or "What is 17% of 2350?"))

The loop worked as in the figure, and the safety guard lives in your code, not in the model’s goodwill. Very small models sometimes get the call format wrong: if that happens, switch to one that lists “tools” (such as qwen3).

Por que o try/except devolve o erro ao modelo em vez de parar? Porque um agente útil se recupera: ele lê “file not found”, tenta outro nome e segue. O MAX_STEPS impede um laço infinito (e uma conta inesperada, se o modelo for pago).Why does the try/except hand the error back to the model instead of stopping? Because a useful agent recovers: it reads “file not found”, tries another name and moves on. MAX_STEPS prevents an infinite loop (and a surprise bill, if the model is paid).

Prática: dar memória de documentos ao agente com RAGHands-on: give the agent document memory with RAG

RAG (Retrieval-Augmented Generation) é buscar, antes de responder, os trechos relevantes dos seus documentos e colocá-los no contexto do modelo. Serve para três coisas: responder sobre dados privados ou recentes que o modelo nunca viu, reduzir invenções (a resposta pode citar a fonte) e evitar re-treinar o modelo a cada mudança nos documentos. A explicação completa, com medições, está na nota AI Engineering; aqui vai só o que precisa para ligá-lo ao agente.RAG (Retrieval-Augmented Generation) means fetching, before answering, the relevant passages from your documents and putting them into the model’s context. It serves three purposes: answering about private or recent data the model never saw, cutting down invention (the answer can cite its source) and avoiding retraining the model whenever the documents change. The full explanation, with measurements, is in the AI Engineering note; here is only what you need to wire it to the agent.

Como funciona: um modelo de embeddings transforma cada trecho de texto em um vetor (uma lista de números) em que textos de sentido parecido ficam perto. Você guarda os vetores num banco vetorial. Na pergunta, transforma-a em vetor também e pede ao banco os vizinhos mais próximos. Para o agente, a busca vira só mais uma ferramenta, ao lado de calc e read_file.How it works: an embedding model turns each piece of text into a vector (a list of numbers) where texts with similar meaning end up close. You store the vectors in a vector database. At question time you turn the question into a vector too and ask the database for the nearest neighbours. For the agent, search becomes just one more tool, next to calc and read_file.

rag.py

import glob, json, os, sys, urllib.request
import psycopg

BASE_URL = os.environ.get("LLM_BASE_URL", "http://localhost:11434/v1")
EMBED_MODEL = os.environ.get("EMBED_MODEL", "nomic-embed-text")
DSN = os.environ.get("PG_DSN", "postgresql://postgres:dev@127.0.0.1:5432/postgres")

def embed(text):
    body = json.dumps({"model": EMBED_MODEL, "input": text}).encode()
    req = urllib.request.Request(f"{BASE_URL}/embeddings", data=body,
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=120) as resp:
        vec = json.load(resp)["data"][0]["embedding"]
    return "[" + ",".join(map(str, vec)) + "]"          # pgvector text format

def setup(conn):
    conn.execute("CREATE EXTENSION IF NOT EXISTS vector")
    conn.execute("""CREATE TABLE IF NOT EXISTS chunks (
        id bigserial PRIMARY KEY, source text, content text, embedding vector(768))""")
    conn.execute("CREATE INDEX IF NOT EXISTS chunks_hnsw ON chunks "
                 "USING hnsw (embedding vector_cosine_ops)")

def ingest():
    with psycopg.connect(DSN, autocommit=True) as conn:
        setup(conn)
        conn.execute("TRUNCATE chunks")                  # simple: re-index everything
        for path in glob.glob("workspace/*.txt") + glob.glob("workspace/*.md"):
            for para in open(path, encoding="utf-8").read().split("\n\n"):
                if para.strip():
                    conn.execute("INSERT INTO chunks (source, content, embedding) "
                                 "VALUES (%s, %s, %s::vector)",
                                 (os.path.basename(path), para.strip(), embed(para)))

def search_docs(query, k=3):
    with psycopg.connect(DSN) as conn:
        rows = conn.execute("SELECT source, content, embedding <=> %s::vector AS dist "
                            "FROM chunks ORDER BY dist LIMIT %s", (embed(query), k)).fetchall()
    return "\n\n".join(f"[{src}] {txt}" for src, txt, _ in rows) or "no results"

if __name__ == "__main__":
    ingest(); print("indexed")

Se o agente responder sem chamar a ferramenta, o modelo é pequeno demais para decidir sozinho; teste um modelo maior ou diga na pergunta “search the documents”.Expected result: rag.py prints indexed; the agent shows on stderr a line such as [step 1] search_docs({'query': 'production backups retention'}) and answers that backups are kept for 14 days. To see the database at work: docker exec -it pg-rag psql -U postgres -c "SELECT source, left(content,40) FROM chunks". If the agent answers without calling the tool, the model is too small to decide on its own; try a larger model or say “search the documents” in the question.

Detalhes que importam. O modelo de embeddings usado para indexar e para buscar tem de ser o mesmo (e a dimensão da coluna, vector(768), tem de bater com a dele). O operador <=> é a distância de cosseno, o mesmo que o índice vector_cosine_ops acelera; o HNSW é um índice aproximado, que troca um pouco de precisão por muita velocidade. Em produção, divida os documentos em trechos de algumas centenas de palavras com sobreposição, guarde metadados (fonte, data, dono) e filtre por permissão na própria consulta SQL, para o agente nunca recuperar o que o usuário não pode ver. Também trate o texto recuperado como dado não confiável: um documento pode conter instruções maliciosas (prompt injection).Details that matter. The embedding model used to index and to search must be the same (and the column dimension, vector(768), must match it). The <=> operator is cosine distance, the same the vector_cosine_ops index speeds up; HNSW is an approximate index, trading a little accuracy for a lot of speed. In production, split documents into chunks of a few hundred words with overlap, store metadata (source, date, owner) and filter by permission inside the SQL query itself, so the agent never retrieves what the user may not see. Also treat retrieved text as untrusted data: a document can contain malicious instructions (prompt injection).

Segurança: o que muda quando o modelo tem “mãos”Security: what changes when the model has “hands”

  • Nunca exponha o servidor à internet. A documentação do Ollama explica que ele escuta só em 127.0.0.1 por padrão e que mudar o OLLAMA_HOST para 0.0.0.0 não adiciona nenhuma autenticação. Use túnel SSH, VPN ou um proxy reverso com autenticação.Never expose the server to the internet. The Ollama documentation explains it listens only on 127.0.0.1 by default and that changing OLLAMA_HOST to 0.0.0.0 adds no authentication. Use an SSH tunnel, a VPN or an authenticated reverse proxy.
  • Menor privilégio nas ferramentas. Dê ao agente só o que a tarefa exige: uma pasta, não o disco inteiro (como o read_file faz); leitura, não escrita; uma conta de banco somente leitura.Least privilege on tools. Give the agent only what the task needs: one folder, not the whole disk (as read_file does); read, not write; a read-only database account.
  • Injeção de prompt. Qualquer texto que o agente leia (página web, e-mail, arquivo) pode conter instruções escondidas. O OWASP lista a injeção de prompt e o excesso de autonomia entre os principais riscos de aplicações com LLMs. Peça confirmação humana antes de ações irreversíveis (apagar, enviar, pagar).Prompt injection. Any text the agent reads (a web page, an email, a file) may carry hidden instructions. OWASP lists prompt injection and excessive agency among the top risks of LLM applications. Ask for human confirmation before irreversible actions (delete, send, pay).
  • Segredos fora do código. Chaves em variáveis de ambiente ou no gerenciador de segredos, nunca no repositório.Secrets out of code. Keys in environment variables or a secrets manager, never in the repository.
