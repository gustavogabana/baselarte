O que é o KimiWhat Kimi is

Kimi é a família de modelos de linguagem da Moonshot AI, empresa de Pequim. O nome serve para duas coisas: o assistente (site e app em kimi.com) e os modelos por trás dele, vendidos por API e, na maioria das versões, publicados como pesos abertos (open weights) no Hugging Face. É por esse segundo motivo que o Kimi aparece junto de DeepSeek e Qwen quando se fala em modelos “abertos” que competem com os fechados.Kimi is the language-model family from Moonshot AI, a company based in Beijing. The name covers two things: the assistant (website and app at kimi.com) and the models behind it, sold through an API and, for most versions, published as open weights on Hugging Face. That second point is why Kimi shows up next to DeepSeek and Qwen when people talk about “open” models that compete with closed ones.

“Pesos abertos” não é “código aberto”. Você pode baixar o modelo treinado e rodá-lo onde quiser, mas os dados e o código de treino não vêm junto, e a licença impõe condições. A seção sobre licença explica o caso do Kimi.“Open weights” is not “open source”. You can download the trained model and run it wherever you like, but the training data and training code do not come with it, and the license sets conditions. The license section explains Kimi’s case.

Esta nota cobre o Kimi K2 (julho de 2025) e o Kimi K3 (lançado em julho de 2026), e o que mudou entre eles. Para a ideia geral de modelos abertos e como rodá-los, veja LLMs de código aberto e agentes; para a arquitetura base de todos eles, Attention Is All You Need.This note covers Kimi K2 (July 2025) and Kimi K3 (released July 2026), and what changed between them. For the general idea of open models and how to run them, see Open-source LLMs and AI agents; for the architecture all of them build on, Attention Is All You Need.

Mixture-of-Experts: por que 2,8 trilhões “custam” 104 bilhõesMixture-of-Experts: why 2.8 trillion “costs” 104 billion

Num modelo denso, cada token passa por todos os parâmetros. Num Mixture-of-Experts (MoE), a parte “feed-forward” de cada camada é dividida em centenas de blocos pequenos, os especialistas. Um pequeno roteador (router) olha o token e escolhe só alguns especialistas para ele; os outros ficam parados. O modelo tem muito conhecimento guardado (muitos parâmetros), mas cada token só “paga” o cálculo dos poucos especialistas escolhidos mais as partes que sempre rodam (como a atenção).In a dense model, every token goes through all the parameters. In a Mixture-of-Experts (MoE), each layer’s “feed-forward” part is split into hundreds of small blocks, the experts. A small router looks at the token and picks only a few experts for it; the others sit idle. The model stores a lot of knowledge (many parameters), but each token only “pays” the compute of the few chosen experts plus the parts that always run (like attention).

A atenção híbrida, em uma figuraHybrid attention, in one figure

A atenção “completa” compara cada token com todos os anteriores, e guarda um cache KV que cresce a cada token. Com 1 milhão de tokens, esse custo (de tempo e de memória) vira o gargalo. A atenção linear troca isso por um estado de tamanho fixo que vai sendo atualizado: custo por token constante, mas com menos “memória exata” do passado. O K3 usa as duas: a linear (KDA, a variante própria da Moonshot) na maioria das camadas e a completa-comprimida (MLA) em uma camada a cada ~4, para não perder detalhe preciso. Os números (69 e 24 camadas) vêm da ficha do modelo; a explicação do porquê é a motivação geral da arquitetura híbrida, não um trecho citado do relatório técnico.“Full” attention compares each token with all previous ones, and keeps a KV cache that grows with every token. At 1 million tokens, that cost (in time and memory) becomes the bottleneck. Linear attention swaps it for a fixed-size state that is updated as you go: constant cost per token, but with less “exact memory” of the past. K3 uses both: linear (KDA, Moonshot’s own variant) in most layers and compressed full attention (MLA) in about one layer out of four, so precise detail is not lost. The numbers (69 and 24 layers) come from the model card; the reason why is the general motivation for hybrid architectures, not a quoted passage of the technical report.

Chamando a APICalling the API

Como o endpoint é compatível com o SDK da OpenAI, o código é o de sempre; só mudam a URL base, a chave e o nome do modelo. Pegue a URL base e a chave no painel da plataforma (não escrevi a URL aqui porque a ficha do modelo não a traz).Because the endpoint is compatible with the OpenAI SDK, the code is the usual one; only the base URL, the key and the model name change. Get the base URL and key from the platform dashboard (I did not write the URL here because the model card does not give it).

from openai import OpenAI

client = OpenAI(
    base_url="<URL base da documentação em platform.kimi.ai>",
    api_key=os.environ["KIMI_API_KEY"],      # nunca no código-fonte
)

resp = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "Explique um índice B-tree em 3 frases."}],
    extra_body={"reasoning_effort": "low"},   # low | high | max (padrão: max)
)
msg = resp.choices[0].message
print(msg.content)                              # a resposta
print(getattr(msg, "reasoning_content", None))  # o raciocínio (sempre vem)
  • O raciocínio custa tokens. Como o modo de pensar está sempre ligado e o padrão é max, uma pergunta simples pode gastar muito mais tokens de saída do que a resposta visível. Use low para tarefas fáceis e meça.Reasoning costs tokens. Since thinking mode is always on and the default is max, a simple question can spend far more output tokens than the visible answer. Use low for easy tasks and measure.
  • Ferramentas e histórico. A ficha diz que, em conversas de várias voltas e chamadas de ferramenta, você deve devolver a mensagem completa do assistente, incluindo reasoning_content e tool_calls, e não só o content. Se o seu código só guarda o texto, o modelo perde o fio do próprio raciocínio. É o mesmo princípio do harness de agente: quem monta o histórico decide o que o modelo “lembra”.Tools and history. The card says that, in multi-turn conversations and tool calls, you must send back the full assistant message, including reasoning_content and tool_calls, not just content. If your code only keeps the text, the model loses the thread of its own reasoning. It is the same principle as the agent harness: whoever builds the history decides what the model “remembers”.
  • Cache automático. A Moonshot diz que o cache de contexto é automático, sem ID, TTL ou parâmetro extra. Na prática: mantenha o começo do prompt (instruções, documentos) igual entre chamadas, porque só o trecho repetido do início é cobrado com desconto.Automatic caching. Moonshot says context caching is automatic, with no ID, TTL or extra parameter. In practice: keep the start of the prompt (instructions, documents) identical between calls, because only the repeated prefix is billed at a discount.

Servindo os pesos (K2 como exemplo)Serving the weights (K2 as an example)

A ficha do K2 recomenda vLLM, SGLang, KTransformers ou TensorRT-LLM e traz comandos prontos. A forma geral é esta (confira as flags no guia de deploy do modelo, que mudam com a versão do motor):K2’s card recommends vLLM, SGLang, KTransformers or TensorRT-LLM and ships ready-made commands. The general shape is this (check the flags in the model’s deploy guide, which change with the engine version):

# forma geral; o número de GPUs e as flags dependem do modelo e da versão
vllm serve moonshotai/Kimi-K2-Instruct \
  --tensor-parallel-size 16 \
  --trust-remote-code

Depois disso você tem um servidor com a mesma API compatível com OpenAI, na sua rede, e o código acima funciona trocando a URL base. Nenhum token sai da sua infraestrutura. Não executei esse comando (não tenho o hardware); ele ilustra o formato.After that you have a server with the same OpenAI-compatible API, on your network, and the code above works by swapping the base URL. No token leaves your infrastructure. I did not run this command (I do not have the hardware); it illustrates the format.

Licença e cuidadosLicense and cautions

  • K2: MIT modificada. A MIT é a licença mais permissiva que existe; a versão “modificada” acrescenta uma exigência de atribuição para produtos muito grandes. Os limites exatos estão no arquivo LICENSE do repositório: leia-o em vez de confiar em resumos.K2: modified MIT. MIT is about the most permissive license there is; the “modified” version adds an attribution requirement for very large products. The exact thresholds are in the repository’s LICENSE file: read it instead of trusting summaries.
  • K3: licença própria. Os pesos e o código saíram sob a “Kimi K3 License”, que não é MIT nem está na lista de licenças aprovadas pela OSI. Segundo o OpenRouter, ela exige exibir “Kimi K3” na interface de produtos com mais de 100 milhões de usuários ativos por mês ou mais de US$ 20 milhões de receita mensal. Fontes divergem nos limites e há relato de uma regra separada para empresas que vendem inferência hospedada; trate os números como não confirmados até ler o texto da licença.K3: custom license. The weights and code were released under the “Kimi K3 License”, which is not MIT and not on the OSI-approved list. According to OpenRouter, it requires displaying “Kimi K3” in the interface of products with over 100 million monthly active users or over $20 million in monthly revenue. Sources differ on the thresholds and there is a report of a separate rule for companies selling hosted inference; treat the numbers as unconfirmed until you read the license text.
  • Para quase todo mundo, um projeto pequeno ou médio fica muito abaixo desses limites. A diferença prática de “aberto” aparece mais na liberdade de hospedar você mesmo, ajustar o modelo e manter os dados em casa.For almost everyone, a small or mid-size project stays far below those thresholds. The practical difference of “open” shows mostly in the freedom to host it yourself, fine-tune the model and keep data in-house.
  • Dados na API oficial. Usar a API da Moonshot significa enviar seus prompts a um serviço de uma empresa chinesa. Leia os termos de uso e de privacidade antes de mandar dados de clientes, código proprietário ou qualquer coisa sensível; se isso for um problema, hospede os pesos ou use um provedor de sua confiança. É a mesma análise que vale para qualquer API de modelo, com as exigências legais do seu setor e país.Data on the official API. Using Moonshot’s API means sending your prompts to a service run by a Chinese company. Read the terms of use and privacy policy before sending customer data, proprietary code or anything sensitive; if that is a problem, host the weights or use a provider you trust. It is the same analysis that applies to any model API, with the legal requirements of your sector and country.
  • Segurança de agentes. Um modelo forte em tarefas longas com ferramentas pode fazer estragos reais se tiver acesso demais. Aplique os cuidados de harness e guardrails: permissões mínimas, ambiente isolado, confirmação humana para ações irreversíveis.Agent safety. A model that is strong at long tool-using tasks can do real damage if it has too much access. Apply the harness and guardrails care: least privilege, an isolated environment, human confirmation for irreversible actions.
